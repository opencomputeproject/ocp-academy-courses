# pronunciation: NDC API -> N D C A P I; NDC -> N D C; OCP -> O C P; API -> A P I; CXL.mem -> C X L dot mem; CXL -> C X L; SNIA -> Snee ah
The draft discusses related interface efforts with different status and scope. Keeping those differences visible makes the technical discussion more productive.

The Storage Networking Industry Association, or Snee ah, publishes the Computational Storage A P I. Version one point one is a published standard for the application interface to computational storage devices. Device implementations still map that interface onto their own capabilities and access mechanisms.

Section four point five proposes extending this starting point across near data classes. It describes broader discovery, generalized data sources and sinks, additional memory attributes, richer operand descriptions, function naming, and placement information. These changes are presented as design intent, rather than adopted specification text. The proposal needs experiments and an agreed definition of the shared contract.

Section four point six describes N D C A P I, a host-side abstraction with an implementation contributed through O C P. The public repository identifies its initial scope as devices exposing C X L dot mem and calls it a proof of concept and reference implementation. It explicitly says it is not a new industry standard.

The useful next question is how these efforts relate. Which abstractions overlap? Where would an adapter sit? Which contracts remain different? The draft does not yet establish an adopted bridge between the approaches. A worked mapping would help contributors compare practical behavior while preserving the distinction between the published interface, the proposed generalization, and the implementation being used for experimentation.
