# pronunciation: DCC -> D C C; PNM -> P N M; PIM -> P I M; DPU -> D P U
Near data computing is a family of placements, rather than a single type of accelerator. The draft includes four classes. Processing in memory, or P I M, places computational capabilities within the memory organization. Processing near memory, or P N M, places compute beside memory. The distinction affects what data can be accessed efficiently and how work can be initiated.

Computational storage places useful computation close to stored data. Examples of functions include filtering, compression, and encryption. A data processing unit, or D P U, can perform work on data in flight in a network path, as well as on data available in its own memory. These are useful starting points for understanding locality. Actual device capabilities vary.

Think about data in use, data at rest, and data in transit. A tensor already resident near a memory engine presents a different integration problem from a stored dataset or a continuous network stream. A common software framework must describe those differences without hiding information needed for a correct placement decision.

The D C C objective is horizontal integration across technologies. It does not mean that every device executes every operation, uses the same memory model, or offers the same guarantees. Discovery and capability descriptions must let software choose valid work for a particular resource. For now, connect each class to its data location. We'll return to how those locations affect the software contract.
