# pronunciation: DCC -> D C C
Choose one workload you know, or use the filtering example. Give it a concrete operation, such as selecting records, computing a matrix-vector product, or inspecting a flow. Identify where its large input resides before the request arrives.

Then describe the current path. Which bytes move, across which boundary, and how often? Describe an alternative placement with the same starting condition and required result. Include the parameters that must travel to the engine and the output that must come back. Avoid adding a performance number unless you have evidence for it.

Finish with a testable sentence. For example: keeping the repeatedly scanned records near the filter engine may reduce host-bound traffic, provided preparation and coordination do not dominate. State what you would measure to accept or reject that claim.

Pause the narration and spend about a minute writing your hypothesis in the contribution worksheet. A useful D C C discussion starts with this context. It lets someone else offer a counterexample, propose a measurement, or explain a device constraint. Your chosen placement is an ungraded design suggestion.
