# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
Flags and masks solve different problems. Flags tell software where a reported warning or alarm needs attention. Masks determine whether particular accumulated counters participate in the health score.

The recommended flag workflow begins with the software interrupt. Software then reads the summary that distinguishes local from remote port flags, and retrieves the detailed module, optical-power, and laser-bias flags in the telemetry reply. These flags are latched and cleared when their registers are read, so harvesting software must preserve what it observes.

The defined score masks apply to the feck counter and link-down counter. Both are excluded from scoring at module power-up. A mask bit of one excludes its counter; zero includes it. Command eight thousand three hex controls those masks.

Masking is not deleting evidence. The counter data can still be retrieved, and the event history is separate. Resetting accumulated counters uses a different command.

Record the effective masks when comparing scores across modules or across time. If two tools apply different participation settings, an identical-looking score may not describe an identical operating condition.
