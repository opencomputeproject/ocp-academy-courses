# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
The host SDK turns the common module interface into operator workflows. The specification describes a sonic implementation and a set of command-line API categories.

Local and remote C M I S access expose register state. Telemetry download displays measurements for a selected endpoint, side, and port. Event tools retrieve recent history in human-readable form, control hysteresis, and clear history only when intended.

Firmware tools handle local or remote maintenance with the appropriate command family and checked lifecycle results. Module-time controls provide the reference needed to compare records, while link-rating display gives a concise entry point into the underlying evidence.

Qualification and diagnostic tools also need capability discovery, counter-mask control, threshold control, and shutdown-state verification. The lower-level commands define those operations even when a particular user interface groups them differently.

Keep reads and configuration changes clearly distinguished. Retrieving history, clearing history, and changing how the module reacts are different actions.

A useful tool reports the destination, supported capability, effective configuration, and command result along with the value. That context is what makes output reliable during a real incident.
