# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
Logs de eventos precisam de detalhes suficientes para serem úteis, mas também precisam de controle. Um link ruidoso pode cruzar um limiar repetidamente. Sem histerese, o registro pode ser preenchido com entradas duplicadas que obscurecem a sequência real dos eventos.

A especificação inclui eventos orientados por limiar, como ligação para cima, ligação para baixo, perda de sinal, perda de link, M P I limite, S N R, pre-feck B E R limite, feck limiar de histograma, feck não corrigível, temperatura do módulo e potência recebida. Também lista suporte para host API para leitura e escrita de histerese de eventos, com valor padrão de 10 segundos na especificação.

Para a versão final, esse valor deve ser verificado em relação à especificação publicada. O conceito é estável: ajustar o comportamento dos eventos para que os logs preservem o sinal em vez do ruído.
Histerese não é sobre esconder fracassos. Trata-se de preservar uma história de fracasso legível. Um log que registra a mesma oscilação muitas vezes pode tornar a causa raiz mais difícil, não mais fácil.
