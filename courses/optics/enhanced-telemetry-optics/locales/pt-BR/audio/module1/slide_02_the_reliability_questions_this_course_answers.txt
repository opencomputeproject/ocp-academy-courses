# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
Este curso é baseado em uma contribuição da comunidade OCP escrita por voluntários de Credo e Oracle. O curso tem quatro partes. Primeiro, enquadramos a lacuna de visibilidade que aparece quando os links ópticos atravessam portas de switch, módulos de transceptores, caminhos de fibra e endpoints remotos que podem ficar dentro de servidores bare-metal.

Segundo, trabalhamos pelas categorias de telemetria que tornam o estado do link acionável: qualidade óptica, qualidade elétrica, erros, comportamento de recuperação, temperatura, energia e contexto administrativo.

Terceiro, analisamos os fluxos de trabalho comando-resposta que movem essa informação entre software do host e módulos. Isso inclui C D B, registros de eventos e acesso remoto C M I S.

Por fim, conectamos o modela telemetria ao gerenciamento de firmware, APIs host e prontidão para implantação. No final, você deve conseguir explicar o modelo operacional sem ficar preso em mapas de bytes.
Tenha uma pergunta em mente enquanto avança pelos módulos: essa informação ajudaria um operador a decidir a próxima ação mais rápido? Se a resposta for sim, isso pertence ao fluxo de trabalho de confiabilidade.
