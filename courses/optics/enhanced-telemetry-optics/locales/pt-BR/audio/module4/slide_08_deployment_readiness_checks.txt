# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
A prontidão para o desdobramento é mais do que uma lista de verificação de campos. É um teste comportamental.

O host pode recuperar a telemetria local? Ele consegue recuperar a extremidade remota direito em um estojo de breakout? O que acontece quando um módulo compatível se comunica com uma óptica terceirizada ou um parceiro não conforme? O tempo de época permite que os registros de eventos se correlacionem com host e monitorando linhas do tempo? É possível descobrir atualização de firmware ser descoberto, transferido, ativado, comprometido ou abortado com status claro a cada etapa?

A especificação também aponta para as expectativas de implementação e repositórios host. Para operadores, isso significa que a interface comum deve ser testável. Uma implantação está pronta quanda telemetria, histórico de eventos, acesso remoto, ciclo de vida do firmware e ferramentas host se comportam de forma previsível sob condições realistas.
Verificações de prontidão devem ser feitas antes do primeiro incidente grave. Se a equipe descobrir durante uma queda de energia que a identidade remota do parceiro ou o tempo do evento são não confiáveis, o sistema telemetria já falhou em seu teste mais importante.
