# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
El documento fuente nombra tres componentes en un sistema de software compatible. El primero es el propio transceptor: firmware, métricas telemetría, registro de eventos y el comportamiento de comandos necesario para exponer esos valores.

El segundo es software del host, normalmente en el interruptor. Esta es la capa que se comunica con el módulo local sobre I al cuadrado C, solicita datos de socios locales o remotos y convierte las respuestas de los módulos en herramientas que un operador puede utilizar.

El tercero es el software de servidor de telemetría. La especificación espera que la telemetría se compile, resuma e informe a nivel de red, pero no prescribe cómo cada operador construye ese lado del servidor. Ese límite es importante. El curso enseña la interfaz común módulo-anfitrión, porque esa es la parte que la contribución estandariza.
Esa visión en capas también ayuda con la responsabilidad. El transceptor posee lo que puede medir y preservar. El host es el responsable de cómo pide y presenta. El servidor telemetría posee una correlación más amplia en toda la entorno a gran escala.
