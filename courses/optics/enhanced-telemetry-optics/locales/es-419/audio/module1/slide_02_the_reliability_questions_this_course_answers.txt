# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
Este curso se basa en una contribución comunitaria de OCP escrita por voluntarios de Credo y Oracle. El curso consta de cuatro partes. Primero, enmarcamos la brecha de visibilidad que aparece cuando los enlaces ópticos atraviesan puertos de switches, módulos transceptores, caminos de fibra y puntos finales remotos que pueden estar dentro de servidores bare metal.

En segundo lugar, trabajamos las categorías de telemetría que hacen accionable el estado del enlace: calidad óptica, calidad eléctrica, errores, comportamiento de recuperación, temperatura, potencia y contexto administrativo.

En tercer lugar, analizamos los flujos de trabajo de comando-respuesta que trasladan esta información entre software del host y módulos. Eso incluye C D B, registros de eventos y acceso remoto C M I S.

Finalmente, conectamos el modelo de telemetría con la gestión de firmware, las APIs del host y la preparación para el despliegue. Al final, deberías poder explicar el modelo operativo sin quedarte atrapado en mapas de bytes.
Ten en cuenta una pregunta mientras avanzas por los módulos: ¿ayudaría esta información a un operador a decidir la siguiente acción más rápido? Si la respuesta es sí, pertenece al flujo de trabajo de fiabilidad.
