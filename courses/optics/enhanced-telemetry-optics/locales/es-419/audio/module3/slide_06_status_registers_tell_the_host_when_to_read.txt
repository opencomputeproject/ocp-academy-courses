# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
La comprobación de estado es lo que mantiene un flujo de trabajo de comando-respuesta honesto. Un módulo puede estar ocupado. Un comando puede completarse con éxito. Un comando puede fallar. software del host debe saber qué estado está viendo antes de considerar una respuesta como válida.

Por eso la especificación incluye C D B, registros de estado de comandos e indicadores de finalización. El objetivo no es solo hacer que el comando sea completo. El objetivo es hacer que el comportamiento de host sea repetible.

Una herramienta fiable para operadores no debería adivinar que la telemetría está lista. Debería activar el comando, consultar para completar, gestionar claramente el fallo y luego recuperar la respuesta. Esa disciplina del software es lo que permite que el comportamiento de los módulos de bajo nivel se convierta en evidencia operativa fiable.
El buen comportamiento de estado también mejora la automatización. Un script puede reintentarlo, retroceder con seguridad, informar de un fallo de comando o detenerse antes de presentar datos obsoletos. Esa es la diferencia entre una herramienta útil y un atajo arriesgado.
