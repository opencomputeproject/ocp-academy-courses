# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
La recuperación de la telemetría es más fácil de entender una vez que el patrón C D B queda claro. El host emite una solicitud. El módulo local recopila o recupera los campos relevantes. El host comprueba el estado del comando. Luego lee la respuesta.

La respuesta puede incluir puntuación de salud, identidad del módulo, contadores de enlaces hacia abajo, tiempo de activación, banderas, métricas de calidad, temperatura, voltaje, energía recibida, comportamiento de error y información feck. El mapa exacto del campo pertenece a la especificación, pero el modelo operativo pertenece a tu cabeza.

Una forma útil de pensarlo es esta: el comando recopila una instantánea coherente para el operador. En lugar de enviar a la gente a perseguir campos dispersos, el flujo de trabajo empaqueta la evidencia necesaria para responder preguntas sobre salud de enlaces.
Para un aprendiz, la clave es la repetibilidad. Una vez que entiendes el patrón, puedes reconocer la misma estructura detrás de diferentes comandos de operador, incluso cuando cambian los nombres de los comandos y los campos carga útil.
