# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
Los registros de eventos necesitan suficiente detalle para ser útiles, pero también necesitan control. Un enlace ruidoso puede cruzar un umbral repetidamente. Sin histéresis, el registro puede llenarse de entradas duplicadas que ocultan la secuencia real de los eventos.

La especificación incluye eventos impulsados por umbrales como conexión de enlace, enlace hacia abajo, pérdida de señal, pérdida de enlace, umbral M P I, umbral S N R, umbral pre-feck B E R, umbral de histograma feck, feck no corregible, temperatura del módulo y potencia recibida. También indica soporte para API del host para leer y escribir histéresis de eventos, con un valor por defecto de 10 segundos en la especificación.

Para la versión final, ese valor debe comprobarse con la especificación publicada. El concepto es estable: ajustar el comportamiento de los eventos para que los registros conserven la señal en lugar del ruido.
La histéresis no consiste en ocultar fracasos. Se trata de preservar una historia de fracaso legible. Un log que registra la misma oscilación demasiadas veces puede dificultar la causa raíz, no hacerlo más fácil.
