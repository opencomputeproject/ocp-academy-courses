# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
Las APIs del host, SDK y de línea de comandos son donde la especificación se vuelve útil para los operadores. La especificación enumera categorías que se corresponden directamente con los flujos de trabajo de campo.

El acceso estándar C M I S permite al software leer el estado local del módulo. El acceso remoto C M I S permite al software extraer datos estándar del extremo lejano. la descarga de telemetría expone parámetros locales o remotos del módulo. Los comandos de registro de eventos leen eventos recientes, borran registros y ajustan la histéresis. Los comandos de firmware gestionan los flujos de trabajo de actualización locales o remotas.

La especificación también incluye la visualización de la hora de época y la valoración del enlace de módulos. Estas categorías importan porque conectan la cadena de evidencia: valores actuales, eventos históricos, correlación temporal y una puntuación de salud concisa. Un buen API hace que esa cadena sea utilizable durante la clasificación y durante incidentes.
Las categorías API también deberían corresponder a documentación y formación. Los operadores deben saber qué comando recupera la telemetría actual, qué comando recupera eventos recientes, qué comando borra el historial y qué comando cambia el comportamiento.
