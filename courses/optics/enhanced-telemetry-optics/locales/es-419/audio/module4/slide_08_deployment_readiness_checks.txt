# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
La preparación para el despliegue es más que una simple lista de campos. Es un control de comportamiento.

¿Puede el host recuperar la telemetría local? ¿Puede recuperar el extremo remoto derecho en una caja de breakout? ¿Qué ocurre cuando un módulo conforme se comunica con un tercero o con un socio no conforme? ¿El tiempo de época permite que los registros de eventos se correlacionen con host y el seguimiento de líneas temporales? ¿Se puede actualización de firmware ser descubierto, transferido, activado, comprometido o abortado con estado claro en cada paso?

La especificación también apunta a las expectativas de implementación y repositorios host. Para los operadores, eso significa que la interfaz común debe ser comprobable. Un despliegue está listo cuando telemetría, el historial de eventos, el acceso remoto, el ciclo de vida del firmware y las herramientas host se comportan de forma predecible bajo condiciones realistas.
Se deben realizar comprobaciones de preparación antes del primer incidente importante. Si el equipo descubre durante una caída que la identidad remota del socio o la hora del evento no son fiables, el sistema telemetría ya ha fallado su prueba más importante.
