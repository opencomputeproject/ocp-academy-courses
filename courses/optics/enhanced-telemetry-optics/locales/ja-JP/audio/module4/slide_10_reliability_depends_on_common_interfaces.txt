# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
信頼性の高い運用には、共通のインターフェースと、その結果を適切に解釈する手順が必要です。

ファームウェア保守では、機能検出、転送、妥当性確認、アクティベート、動作検証、コミットを分けます。ホストはI2Cを使うローカルの制御点であり続け、モジュールが帯域内通信でリモートパートナーにアクセスします。

ホストツールは、対応機能、ローカルとリモートの測定値、側ごとの評価、スコア設定、イベント履歴、モジュール時刻、ファームウェアの結果をまとめます。スイッチ自身の受信機のエラー測定値も加わります。

設定はエビデンスと結び付けたまま保持します。カウンターマスクはスコアへの算入を左右します。閾値はスコア帯を決めます。自律シャットダウンは別の応答であり、リセット後は既定で無効で、特定可能な異常原因とイベント記録を残します。

エンドポイントの識別情報と有効なタイムスタンプにより、これらが結び付くと、現在の状態がタイムラインになり、そのタイムラインがファブリック全体の信頼性の把握を支えます。

検証やインシデントの際は、このモデルで的確に問いかけてください。どの受信機、どのパートナー、どの設定、どのイベント、どの完了済みコマンドが、その結論を裏付けるのでしょうか。
