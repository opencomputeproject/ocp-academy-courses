# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
無停止のファームウェア保守には、1つのコマンドの成功ではなく、管理されたライフサイクルが必要です。

リモートのイメージ情報を確認し、ダウンロードを開始します。ファームウェアをブロック単位で転送し、各結果を確認します。ブロック転送が失敗した場合は、不完全なイメージのまま続行せず、ダウンロードを中止して後処理を行います。

すべてのブロックが届いたら、ダウンロード完了コマンドがその段階を検証します。イメージのチェックサム不正などの失敗は、ダウンロードが成功していないことを意味します。アクティベートに進んではいけません。

完了が成功したら、新しいイメージを実行し、その動作を検証します。その後で初めて、実行中イメージを今後のリセット時の既定値としてコミットします。実行とコミットの区別は、モジュールが今どう動作し、リセット後にどう動作するかを理解する上で重要です。

ローカルモジュールは、これらの操作を帯域内インターフェースで選択したリモートパートナーに伝えます。手順全体を通して、パートナーの識別情報を維持してください。

無停止機能も、導入環境での検証が必要です。稼働中にこのワークフローを信頼して使う前に、実際のトラフィックの継続性、コマンド状態、復旧動作、保守ポリシーを確認します。
