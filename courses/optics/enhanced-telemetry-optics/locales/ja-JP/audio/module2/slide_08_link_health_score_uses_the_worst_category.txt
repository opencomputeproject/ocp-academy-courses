# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
平均化は安心感にもなり得るし、危険でもあります。5つのカテゴリーが優れていて、1つのカテゴリーが不合格であれば、平均は許容範囲に見えるかもしれません。これは操作には役に立ちません。なぜなら、失敗したカテゴリはリンクを切断してしまう可能性があるからです。

仕様ではリンク健康評価の最低スコアカテゴリを選択することでこれを処理します。簡単に言えば、最も弱いカテゴリーが報告される健康状態を左右します。しかし、すべての指標がすべての展開で同じ意味を持つわけではありません。つまり、要約で注目に値する一つのカテゴリーを隠してはいけません。

これは信頼性の良い原則です。ヘルススコアは、アクション信号を保持する場合にのみ情報を圧縮すべきです。圧縮によって失敗したフィールドが隠されてしまうと、スコアはトラブルシューティングツールではなくダッシュボードの装飾品になってしまいます。
だからこそ、健康スコアは説明可能であるべきです。オペレーターはスコアからカテゴリー、カテゴリーから証拠へとドリルできるべきです。その道筋がなければスコアは十分ではありません。
