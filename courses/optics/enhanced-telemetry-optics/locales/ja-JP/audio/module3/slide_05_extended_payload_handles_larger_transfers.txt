# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; SDK -> S D K; API -> A P I
すべての返信が地域のペイロードにぴったり合うわけではありません。仕様書では、より大きな転送のために拡張されたペイロードページ、A0hからAFhまでを記述しています。最大2048バイトの容量を記載しています。

運用上の考え方はシンプルです。コマンドのワークフローは変わりませんが、データ領域は拡大します。ソフトウェアはコマンドを準備し、それをトリガーし、状況をポーリングし、返信を取り戻します。違いは、返信の一部がローカルのペイロードだけでなく、拡張されたペイロードページに存在する場合がある点です。

長さとチェックフィールドは重要です。なぜなら、ホストは応答にどれだけのデータが属しているか、そして正しく取得されたかどうかを知る必要があるからです。大きな転校は規律の重要性を増し、減らすわけではない。
拡張ペイロードは、より豊かな返信やログに特に重要です。テレメトリがより役立つようになるにつれて、返信にはより多くのスペースが必要になるかもしれません。ワークフローは、大きな応答を特別なケースに変えることなくスケールするべきです。
