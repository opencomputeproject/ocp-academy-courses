# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
テレメトリ要求には、対象、側、ポートという3つの情報が必要です。

対象では、ローカルモジュールまたはリモートパートナーを選びます。側では、ホスト側の電気インターフェースまたはメディア側の光インターフェースを選びます。ポートは該当するデータパスを識別します。これは1つのモジュールが複数のパートナーに接続する場合に重要です。

コマンド8001hは、その選択に対応するテレメトリを返します。ソフトウェアは要求を準備し、発動し、状態をポーリングして、正常に完了した応答を読み取ります。

応答は、対象がオンラインでアクセス可能かを示します。評価値と最低カテゴリのビットマップ、モジュールのシリアル識別情報、リンクダウン回数、稼働時間、フラグ、信号品質の測定値、環境値、FEC情報が含まれます。

応答フィールドの一部は、各レーンを個別に列挙するのではなく、最悪のレーンを要約します。光パワーには最小値と最大値が含まれます。ポートのサマリーから詳細な調査に進むときも、この集約方法の情報を保持してください。

オフラインの対象は、メトリクス値がゼロの健全な対象ではありません。アクセス可能性を明示します。ローカルとリモートの要求で共通のワークフローを使いますが、エンドポイントとインターフェースの情報は、エビデンスに結び付けたままにしなければなりません。
