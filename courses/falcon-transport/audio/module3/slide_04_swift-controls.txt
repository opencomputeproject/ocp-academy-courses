# pronunciation: NIC -> Nick; RUE -> R U E; CSIG -> C S I G; PLB -> P L B; ACK -> acknowledgment; version numbers spelled out.
Swift uses two congestion windows because network queuing and receiver pressure are different problems. The fabric window, f c w n d, responds to measured fabric delay. The Nick window, n c w n d, responds to remote receive-resource occupancy. Falcon reports a quantized level derived from its network receive packet and buffer pools. This is protocol feedback, not a description of how to build a buffer allocator.

For ordinary acknowledgments and applicable negative acknowledgments, Swift smooths its measurements and compares them with its targets. The fabric control can increase available work when delay permits, or reduce it when delay is too high. The Nick control responds to receive pressure. A resource-exhaustion negative acknowledgment has a specific Nick-window reduction rule. Retransmission events also have a defined fabric response. A controller therefore needs the event type as well as a delay number.

Window guarding prevents repeated reactions to closely related feedback. Swift avoids reducing the fabric window repeatedly within one round trip, and avoids repeatedly changing the Nick window in the same direction within one round trip. The specification maintains time markers for those guards, including timestamp wraparound handling.

With multipathing, fabric windows are per flow, while the Nick window remains per connection. Aggregate transmission gates still apply before a path is selected. A flow with a fabric window below one uses pacing based on its round-trip time and fractional window. Only packets assigned to that sub-unity flow receive that per-flow pacing. These controls are complementary: window accounting bounds outstanding work, while pacing spaces eligible packets in time. No single feedback sample promises a fixed latency or throughput result.
