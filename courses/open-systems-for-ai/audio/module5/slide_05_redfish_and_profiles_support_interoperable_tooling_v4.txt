# pronunciation: OCP -> "O C P"

Redfish provides a standard management interface and data model for supported resources and actions. Common interface language helps tools interpret equipment information consistently. It does not mean every product exposes the same capabilities.

Profiles define selected capability requirements for a particular purpose. Examples can address baseline behavior, servers, racks, accelerators or cooling equipment. A client and a product need to agree on the relevant requirements and supported functions, rather than relying on the word Redfish alone.

Keep conformance and implementation evidence separate. Ask which profile and revision apply, which functions are supported, and how the product has been checked. A service can expose an interface while still depending on the host software or other components for availability.

The O C P Hardware Management Project and DMTF resources provide the routes to current documents. Profile status can change as community work develops. For a deployment, verify the actual published material and selected implementation. For this course, the main lesson is that common interfaces and explicit capability requirements make management integration more repeatable when the participating implementations conform.
