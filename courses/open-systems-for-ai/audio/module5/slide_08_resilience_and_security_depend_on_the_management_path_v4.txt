# pronunciation: RAS -> "R A S"

Availability depends on the management path as well as the equipment being managed. An out-of-band arrangement can separate selected management functions from the main workload environment. Its actual independence depends on how power, networking, hardware and software are implemented.

A Redfish software service running on a network operating system can provide useful manageability. If that operating system is unavailable, the service may be unavailable too. The interface name alone does not establish independence from the host or from a shared failure.

Review reliability, availability and serviceability, often abbreviated R A S, together with security. Operators need suitable access control, protected firmware update and a recovery path. Those functions also need to behave appropriately when a component or connection fails.

Use concrete failure cases. Remove the main workload software from the picture and ask what can still be observed. Consider a lost management connection, a failed update and a loss of the relevant power source. Verify the intended behavior and escalation procedure for each case. A management design is resilient when its dependencies and recovery boundaries are understood and demonstrated.
