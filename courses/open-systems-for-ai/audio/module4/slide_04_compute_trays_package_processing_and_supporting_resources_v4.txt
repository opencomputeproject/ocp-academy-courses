# pronunciation: DC-MHS -> "D C M H S"; HPM -> "H P M"

A compute tray packages processing resources and the components that support them. Depending on the architecture, it can contain host processors, accelerators, local memory, interfaces and storage. The arrangement reflects the workload and the system's physical and service requirements.

A host processor module, or H P M, provides a defined modular boundary for host processing. Its name does not describe every possible compute-tray implementation. Check what the selected architecture includes, how the module connects, and which functions remain elsewhere in the system.

The tray also has interfaces to the rack. Power, coolant, management and data connections must fit the intended arrangement. Airflow may remain necessary for components outside the liquid path. Connectors need the required alignment and service access, and the tray needs an appropriate handling process.

Use the compute-tray map to ask clear questions. Which resources execute the workload? Where is their memory? Which paths connect them? What does the tray require from the rack and facility? For additional modular-design context, the linked D C M H S workshop presentation is optional reference material. The course's integration decisions depend on the current documents and evidence for the selected configuration.
