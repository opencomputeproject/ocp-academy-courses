# pronunciation: L.O.C.K. -> "lock"; OCP -> "O C P"

Management and security cross the boundaries between components. A controller may observe equipment state, expose supported management functions and coordinate local actions. A secure control module can provide a defined arrangement for selected management and security functions within an architecture.

Caliptra is an open hardware and firmware root of trust integrated into a chip. It supports device identity, measured boot and attestation. The project links O C P's specification work with development hosted by the Linux Foundation's CHIPS Alliance.

O C P lock stands for Layered Open-source Cryptographic Key Management. It is an optional Caliptra feature set for self-encrypting storage. Caliptra acts as a protected Key Management Block. Drive firmware requests key operations without receiving plaintext media-encryption keys. The device's encryption engine performs the data encryption. This separates key protection from storage policy and data processing.

Keep responsibilities clear. Who can request an update or an erase? Which component authorizes the request? What happens if an operation fails? A hardware root of trust supports the security design; credentials, access control, recovery and correct integration still need review.

A separate management tray is one implementation choice. Document the actual trust boundaries and dependencies alongside compute, network and power interfaces. The linked lock Academy course explains the protected key lifecycle. Use the Caliptra project reference to follow the CHIPS Alliance work.
