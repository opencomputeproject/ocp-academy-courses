# pronunciation: AI -> "A I"

An A I workload creates demands that travel through the whole infrastructure. More computation may require more accelerators. Those accelerators need memory capacity, memory bandwidth and a way to exchange data. They also need electrical power, a heat-removal path and space for installation and service.

Different workloads put pressure on different parts of that chain. Training a large model may involve repeated exchanges among many accelerators. Serving that model may be more sensitive to response time, memory capacity or how requests are divided among resources. A fast processor does not remove a bottleneck elsewhere.

The location matters too. The A I Computing Continuum Project considers deployments beyond centralized hyperscale facilities, including regional, enterprise and user-adjacent environments. A smaller site still has to make the same basic interfaces agree, often with different limits on power, cooling, space and connectivity.

Treat growth forecasts as context for planning. Ask which workload, which measure and which period a number describes. For a real deployment, start with the intended work and follow its requirements through the system.
