Use the Hub-to-Compute connection as a concrete reading exercise. Chapter five identifies the functional relationships: coherent memory traffic, interrupts, security communication, system control, boot code image loading, boot sequence control, and debug. These are architectural obligations for the pair. They are not seven interchangeable names for one high-speed link.

Chapter seven then maps interface requirements to protocols and transports. The protocol defines the exchanged meaning and behavior. The transport supplies the mechanism carrying it. Read both dimensions and check versions for equality or mutual compatibility. F C S A references available standards rather than defining every new mechanism itself. Some mapping entries are explicitly marked to be defined. Preserve those gaps in the integration review instead of filling them with an assumption.

For example, the published level-one coherent-memory protocol rule names Amba C H I Chip-to-Chip. The Summit discussion also considers future alignment with Amba C two C. A future direction does not silently replace the mapping in version one point one point zero. Likewise, a transport entry cannot prove that an unspecified protocol has been settled. Build a pairwise record with function, applicable rule and level, protocol, transport, version, and unresolved agreement. That record is much more informative than writing one interface-standard name beside a line.
