The candidate accelerator joins a Compute and Hub system. The first supplier description says it performs coherent accesses, but that phrase leaves a critical ambiguity. Ask whether it contains caches that participate in coherency with other chiplets, or instead relies on input output coherency without its own coherent cache. Then locate translation and access protection, and request the relevant functional interfaces and configuration restrictions.

The host responsibilities matter as much as the accelerator's feature list. An untranslated or remote-translation arrangement needs the matching system-side functions and the correct interface behavior. A candidate that advertises a capability in one configuration may require different settings when used as another F C S A type. Include the intended system composition and deployment when asking for evidence.

Spend about seven minutes on workbook exercise two. It provides two supplier responses with different cache and translation behavior. Propose the next specification sections to read and list the evidence still missing. You do not need to invent a complete chiplet from the response. A useful outcome is a defensible candidate classification plus a small set of questions that would confirm or reject it. This habit avoids turning an incomplete data sheet into a confident integration commitment.
