There are ten defined chiplet types. Three establish the main compute and hub roles: Compute one, Compute two, and Hub. Five expansion types distinguish fully coherent processing from input output coherent processing and then distinguish translation arrangements. The remaining two types provide input output functions: the input output Chiplet and the input output Controller Chiplet. This grouping is a navigation aid; the exact functionality and interface rules remain in each type's section.

A type is more than a product category. It specifies on-chiplet functionality and a mandatory interface set. A vendor may implement additional functions and interfaces. A chiplet can satisfy more than one type when it meets the requirements of each, although integration-specific configuration may be needed. The type decision is therefore not always an exclusive choice among ten labels.

For example, knowing that a component accelerates inference does not establish whether it has coherent caches or where addresses are translated. Nor does a process node, package footprint, or supplier name answer those questions. Those facts matter elsewhere in engineering, but they cannot replace the architectural evidence. Use the type map to find the likely section, then test the candidate against its required capabilities and interfaces. The workbook contains the full names so that the shortened labels on a topology do not become an ambiguous supplier declaration.
