# pronunciation: F C S A; input output; nonvolatile memory; chiplet root of trust for attestation.

A trust decision describes an accepted state; it is not permanent permission detached from that state. Firmware update, reset, warm reset, chiplet fault, debug unlock, and recovery can change the basis of composition assurance. The system root of trust must trigger revalidation when such a change can affect the Security Platform. Chiplet-local enforcement and reporting remain important during runtime.

Freshness matters because a report describing yesterday's accepted state cannot establish the current state after a change. Rollback and revocation status matter because an apparently authentic identity or image may no longer be authorized. Topology and role bindings matter because moving a valid component into a different composition can change its security effect. The review should connect each relevant event to the evidence that becomes stale and to the authority responsible for responding.

Spend about eight minutes on exercise four. Pick one state change for the accelerator, identify the invalidated assumption, and define what the product does until appraisal succeeds. Then state the evidence needed to validate that response. If the product relies on an external verifier that is unavailable early in boot, the policy must preserve a restricted bootstrap state until the necessary appraisal succeeds. Do not solve that dependency by assuming the complete Security Platform already exists; formation must not depend on services available only after formation.
