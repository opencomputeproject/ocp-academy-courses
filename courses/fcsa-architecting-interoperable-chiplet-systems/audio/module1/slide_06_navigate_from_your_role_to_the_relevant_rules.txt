# pronunciation: F C S A; input output; nonvolatile memory; chiplet root of trust for attestation.

A system designer starts with system requirements and chooses the system type, chiplet roles, quantities, and combinations. A standalone chiplet designer starts with intended deployments and the required functionality and interfaces. These are two entry points into the same specification. Neither role can stop after reading only a marketing description of a type.

For our running case, the integrator records a Compute and Hub system, an accelerator under consideration, and the software boundary. The next questions concern coherent caches, address translation, and the interfaces required by the chosen pair. After selecting the roles, the review moves to functional interface requirements, common boot and control components, implementation mappings, and security. The route through the chapters follows dependencies rather than document length.

Open workbook exercise one. In the first scenario, application processors share one operating system while a separate accelerator contributes to that system. In the second, two independently managed systems share a package. Write the boundary of the proposed F C S A claim for each. Then draft the minimum information missing from the sentence, this package is F C S A compatible. Spend about six minutes before reading the worked response. The aim is to make the claim testable, while leaving detailed type selection for the next module.
