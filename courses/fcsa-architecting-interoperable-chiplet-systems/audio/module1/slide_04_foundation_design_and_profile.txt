Read the architecture as three extending layers. The foundation establishes common concepts and basic requirements without choosing every detail of a product. A design specification adds requirements for a particular system design. For example, that layer could specialize the architecture for an instruction set. A profile then extends a design specification for a market, deployment environment, or focused function. The higher layer includes the lower layer's requirements and adds to them. This is a requirements relationship, not a menu in which a profile replaces the foundation.

F C S A concentrates on a system that could have been a monolithic design and is now partitioned across chiplets. An operating system or hypervisor provides a useful boundary for the single system software image. Some packaged devices remain abstracted by established peripheral or memory standards. F C S A can describe the system that uses those devices without defining every device inside the package.

There is another useful boundary: a chiplet type can apply to a composite structure integrated as one unit. The tightly coupled internal dies of that structure are not automatically independent F C S A chiplet types. Before drawing a type box around every die, establish the unit that the architecture actually exposes. These distinctions keep our accelerator example focused on the obligations that matter.
