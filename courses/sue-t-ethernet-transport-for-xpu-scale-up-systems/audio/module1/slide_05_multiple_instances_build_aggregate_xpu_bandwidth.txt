# pronunciation: SUE-T -> "S U E T"; XPU -> "X P U"; Gb/s -> "gigabits per second"; Tb/s -> "terabits per second"
An accelerator can integrate multiple S U E T instances. Each instance supplies network connectivity through one or more ports, so the integration can scale aggregate bandwidth by adding transport instances around the accelerator.

The specification gives a concrete example. One instance supports one point six terabits per second using either two eight-hundred-gigabit ports or four four-hundred-gigabit ports. Six such instances provide nine point six terabits per second of aggregate scale-up bandwidth.

Those numbers illustrate an integration arrangement. They don't specify how every accelerator must be built or establish the useful throughput of a particular workload. The example helps explain why instance area, buffering, and state matter: an endpoint design can be replicated several times within the same accelerator.

The later load-balancing discussion distinguishes distributing work across instances from assigning packed work to ports within an instance. For now, keep the deployment picture simple. One accelerator can contain several transport instances, and one transport instance can expose several Ethernet ports.
