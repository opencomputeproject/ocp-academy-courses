# OCP Ready™ Requirements for Energy Storage Systems

A practical guide to ESS deployment, safety, standards, and OCP Ready™ application in data centers.

This course source is intended for PR-friendly editing. Change slides, quiz content, glossary links, and figure assets in `course.json`. Change narration in `audio/moduleN/slide_*.txt`. Generated audio and SCORM runtime files are not checked in.

## Modules

| Module | Title | Summary |
|---|---|---|
| 1 | Why ESS Requirements Matter In AI Data Centers | The shift toward distributed ESS, the scope of the white paper, and the stakeholders who must align. |
| 2 | Deployment Models, Architectures, And Technologies | How ESS placement, coupling, control, and storage technology shape the compliance path. |
| 3 | Safety Hazards, Mitigation, And Operations | Electrical, thermal, gas, explosion, chemical, detection, ventilation, suppression, and response considerations. |
| 4 | Codes, Standards, And OCP Ready™ Application | How to navigate local codes, international standards, insurer guidance, and OCP Ready™ ESS parameters. |

## Media

Course-owned media is stored in `figures/`. Editable, localized static diagrams
are generated by `scripts/build_static_figures.mjs`; their labels remain readable
in the adjacent source data. Review changed artwork before replacing its
`figure.text_inventory` hashes.

The current animation sources, reviewed cue maps, encoding tools, and validation
instructions are in [animations/full-v4](animations/full-v4/README.md). Modules
1-3 use narration-synchronized, single-pass teaching videos that hold their final
picture. Module 4 retains the existing independent workflow loop. Every language
edition has localized teaching media and shares the English catalog poster.

## Build

Narration uses full Eleven v4, the approved language-specific voice, and
pitch-preserving 1.18 pacing. The learner's initial speed remains 1.0. Deliver
44.1 kHz, 96 kbps CBR mono MP3s; keep native provider files, authoring WAVs, and
generation receipts outside source control and the SCORM ZIP.

From the repository root, rebuild with reviewed WAV masters that match the
committed animation cues:

```bash
EXISTING_AUDIO_DIR="/path/to/reviewed-v4/audio" \
  ./scripts/build-course.sh ocp-ready-requirements-for-energy-storage-systems
```

Use the corresponding `locales/<BCP-47 tag>` course path and that locale's WAV
masters for a translated build. The finished course, SCORM 1.2 ZIP, and separate
LMS catalog exports are created under `build/` by default.

For fresh synthesis, stage the source and scripts with the maintained authoring
workflow, set `ELEVENLABS_API_KEY`, and generate the final full-v4 recordings.
Review pronunciation and projection, then refresh and review the affected
animation cues and encodes using the linked animation instructions. Update the
reviewed figure metadata before assembling the release with those masters.
Do not reuse timing metadata from a different recording.

The course-owned `scripts/build_resources.py` preflight is called by the existing
build wrapper. It stops before rendering/packaging when a video, recording, or
spoken script differs from its reviewed pairing. It does not infer listening
approval, refresh review hashes, or retime media automatically.

Run its focused integrity tests with:

```bash
python3 courses/ocp-ready-requirements-for-energy-storage-systems/scripts/test_build_resources.py
```

Formal LMS copy is maintained separately in [lms-catalog.md](lms-catalog.md) and
`lms-catalog.json`, with localized equivalents under each locale. The approved
45-minute learner-time estimate is not a measurement of every language's audio.
