Start with a storage drive and the published product-type mapping.

Common requirement groups apply across products. They include general security properties, business processes, software, firmware, and cryptography. The exact requirement text determines what must be supported.

Then consider applicable conditions. A physical product brings hardware requirements. A product with a C P U or a P C I E interface brings the corresponding requirement groups. Check the actual design rather than assuming every drive is identical.

The disk-specific additions include sanitization under requirement S T R G zero zero two. For a self-encrypting drive, the mapping also includes S T R G zero zero one, concerning standardized storage security functionality. Those additions sit alongside the common and conditional groups.

An accelerator has a different set of additions, including system memory and root-of-trust requirements. Platform requirements also apply if it isn't enclosed in a server. The comparison shows why product type matters. Use the full mapping and requirements for the real product, rather than treating this illustration as the entire requirement set.
