# pronunciation: NIC -> Nick; BMC -> B M C; NC-SI -> N C S I; RBT -> R B T; RBT_ISOLATE -> R B T isolate; PCIe -> P C I E

For a card that supports N C S I over R B T, the B M C has a management path that does not depend on the host CPU. Two traffic types use this path. Control traffic configures the network controller and queries its state. Pass-through traffic carries the B M C's network packets through the Nick's Ethernet port. A management controller may use control traffic without enabling pass-through.

Now consider two populated slots sharing one R B T interface. Hardware arbitration passes a token around a closed ring so that the cards do not transmit on the shared interface at the same time. The active transmitter changes, but the shared connection remains.

An empty slot, a powered-off slot, or a slot in ID Mode must be bypassed in the arbitration ring. The R B T isolation mechanism also keeps an inactive slot from disturbing the shared bus. Bypassing the arbitration path and isolating the data path are different responsibilities, and the baseboard must handle both.

These examples explain management traffic, arbitration, and isolation. They do not define a complete platform hot-swap procedure; the system-level hardware and software design still has to provide that behavior.
