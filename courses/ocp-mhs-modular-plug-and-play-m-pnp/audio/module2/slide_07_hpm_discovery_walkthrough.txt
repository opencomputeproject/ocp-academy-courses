Start the walkthrough with the qualifiers. A process step may execute only in its listed power states. Security steps are required when the platform security profile requires them; they are not universally required, but they are not freely optional when that profile applies.

Retrieve the required local H P M description and handle extended data with its stated failure rules. Then establish the primary programmable device's electrical connectivity. The preferred method uses ConnectedBuses in the H P M JSON. The legacy method uses existing information in the B M C.

Static description is a separate question. Option A uses a GUID to identify a non-self-describing implementation. Option B combines factory JSON with a patch. Option C provides resident self-description. Those options must not be relabelled as the three interoperability levels.

Continue with the supported dynamic or extended descriptions. If the security profile requires S P D M, the Security Protocol and Data Model, or other verification, perform those checks at the permitted states. Every required dependency and failure outcome still applies.
