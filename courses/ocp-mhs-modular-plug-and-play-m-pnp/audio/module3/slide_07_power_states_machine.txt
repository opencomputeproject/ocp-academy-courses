Table fifteen defines ten power states. Three are explicitly named Hold-Off: Standby, S five and S zero. S zero Run-Bios-Boot is a separate state that permits code execution; it is not a fourth Hold-Off.

The early states reveal why the S C M has a separate tracking role. G three, Pre-Standby and Standby Hold-Off all have the zero encoding at the P D because the programmable device is powered off or held in reset. The S C M keeps the information needed to distinguish them.

The encodings are non-monotonic relative to the transition order. For example, the SoC Ramp encoding is numerically above S zero Hold-Off. The encodings are state identifiers, not a counter that increments with each transition. Hold-Off states create useful checkpoints, but the security profile determines the required verification. Distinguish the state mechanism from a universal claim that every tier always receives the same attestation.
