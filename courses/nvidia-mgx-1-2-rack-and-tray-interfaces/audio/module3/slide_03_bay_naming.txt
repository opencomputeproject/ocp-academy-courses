# pronunciation: MGX -> M G X; HPM -> H P M; DC-SCM -> D C S C M; DC-SCI -> D C S C I; UQD -> U Q D; UQDB -> U Q D B; MQD -> M Q D; MQDB -> M Q D B; RU -> rack unit; PCIe -> P C I Express; PG25 -> P G twenty-five; Hi-Pot -> high-pot; CRPS -> C R P S; versions and technical quantities spelled out.
The naming scheme makes a bay's allocation explicit. Every system is described with four bay locations across its width, in both the front and rear. Chassis height is described by rows, with each row representing one rack unit. The bay name combines row location, short or long depth, chassis position, and bay type.

A wider bay lists all the positions it consumes. A taller bay lists all its occupied rows. Those fields prevent the same physical space from being assigned twice when a population is assembled from different module types.

Consider the Type D example. A long Type D bay in the leftmost location of the bottom rack unit is named Row one, Long one point two, D. The one point two field indicates locations one and two; it is not a decimal measurement. If that example occupies two rack units, the row field becomes Row one point two. Now the name identifies both rows one and two and locations one and two.

Read this as an allocation statement. It does not by itself establish that the chassis supports every retention or connection feature for that population. The contribution says bay quantities and locations are restricted by bay type, depth, and chassis design.

For a review exercise, decode one multi-row bay name and mark the positions it occupies. Then identify the neighboring modules and the relevant divider interfaces. A valid layout requires consistent allocation before the width, depth, retention, and connector details can be checked.
