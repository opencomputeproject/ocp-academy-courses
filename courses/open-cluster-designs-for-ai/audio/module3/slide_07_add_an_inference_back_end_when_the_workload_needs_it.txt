Inference uses a different decision. If each model-serving request is handled within one server, with no cross-host dependency on its critical path, the Minimal Inference profile omits the scale-out back-end. It still needs the front-end and storage path, a gateway for external service traffic, in-band management, and an independent out-of-band path. Now let the model or a critical dependency span hosts. The Distributed Inference profile adds back-end connectivity for that communication. It retains the front-end and storage arrangement and the gateway role. Follow that addition in the animation: an accelerator back-end appears because the workload needs it. Do not confuse Minimal Inference with Minimal Training. Also, a service can have many independent serving hosts without requiring a back-end between them. The dependency pattern, rather than server count alone, drives this choice.
