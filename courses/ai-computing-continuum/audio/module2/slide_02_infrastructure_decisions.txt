# pronunciation: AICC -> "A I C C"; AI -> "A I"; OCP -> "O C P"
By the end of this module, you'll be able to connect four levels of infrastructure decision.

You'll identify the five domains in the current O C P A I C C scope and explain the role each one plays.

You'll compare common constraints across enterprise, telecom, industrial, office, and remote deployments, including power, cooling, space, serviceability, environmental exposure, and growth model.

You'll explain how open interfaces let servers, racks, cooling, power, networking, and wireless components form repeatable solutions without forcing every site into the same physical design.

And you'll be able to explain how one inference serving deployment coordinates specialized resources. That means recognizing model-aware routing, prefill, key-value cache state, iterative decode, data access, telemetry, and security as infrastructure concerns. These functions may use different instances, worker pools, or memory tiers while remaining within one site.

Together, these ideas turn the continuum from a list of locations into an engineering problem that O C P contributors can divide into useful, testable pieces. Extending work across sites is a separate architecture decision that we'll examine in the next module.
