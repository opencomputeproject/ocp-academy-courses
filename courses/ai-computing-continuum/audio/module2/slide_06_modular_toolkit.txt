# pronunciation: AICC -> "A I C C"; AI -> "A I"; OCP -> "O C P"
The A I C C hardware scope forms a modular toolkit.

Open server architectures define reusable node and accelerator interfaces. Open solution architectures connect those nodes to rack, cooling, power, and facility decisions. Building-block architectures make important physical functions replaceable and composable. Autonomous wireless work brings A I capability into radio environments. Connectivity provides the fabrics within and between deployments.

The toolkit must remain site-aware. A standard interface is valuable when it allows different power envelopes, cooling methods, service models, and environmental protections behind that boundary.

It must also support the changing structure of inference. Within one serving deployment, compute, memory, cache, storage, routing, telemetry, and trust may use different instances, worker pools, and resource tiers while still serving one request.

O C P's role is not to prescribe one software stack or one product. It is to create open hardware specifications and ecosystem alignment that make interoperable choices possible as deployments scale up and scale out. Connecting work across sites adds a different set of service and communications requirements, which we'll examine next through the Scale-Across, Sync-Across, and Reach-Across models.
