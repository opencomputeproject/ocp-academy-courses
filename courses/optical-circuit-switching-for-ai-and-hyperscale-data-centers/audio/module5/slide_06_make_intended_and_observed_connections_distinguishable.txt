# pronunciation: OCS -> O C S; EPS -> E P S; OEO -> O E O; TPUv4 -> T P U version four; GPU -> G P U; GPUs -> G P Yous; ACTINA -> Actina; MoE -> M O E; OCS-BCube -> O C S B Cube; gNMI -> g N M I
The 2026 interfaces discussion highlights a practical control problem: software needs a consistent way to describe devices, request connectivity and observe state. OpenConfig and YANG provide a modeling approach, while g N M I offers operations such as Get, Set and Subscribe. These names refer to the management interface, not to the optical mechanism itself.

A requested connection and an active connection should be distinguishable. A controller may intend a new circuit while a device is still applying or validating it. Device capabilities can also differ, so software must discover and respect supported behavior. Shared models help make those differences explicit. The cited presentations reflect work in progress; this course does not assert a single current specification version from slides with differing release labels.
