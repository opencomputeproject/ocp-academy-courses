# pronunciation: AI -> "A I"

Changing the number of participants is a state transition, not just a capacity event.

An independent serving replica may become eligible for requests after it loads the approved model and passes readiness checks. A training participant has a different contract. It needs the correct role, state and communication-group membership before taking part in coordinated operations.

Supported frameworks can provide elasticity, including changing worker groups through restart and recovery mechanisms. That does not imply that an arbitrary device can join an operation already in flight. Membership, rank assignments and workload behavior may change when the group is re-formed.

The example team therefore needs a defined transition boundary. It should explain what triggers the change, which state is restored, how the participants are initialized, and which checks establish readiness to resume.

The right question is not whether distributed A I can ever scale dynamically. It is whether this implementation supports this change with the required state and behavior.
