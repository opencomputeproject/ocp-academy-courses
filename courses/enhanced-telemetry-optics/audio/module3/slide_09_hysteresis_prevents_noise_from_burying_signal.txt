A useful event log needs both detail and restraint. A noisy link can repeat the same condition often enough to overwrite the circular buffer with duplicates.

The specification uses programmable hysteresis with a ten-second default. This limits duplicate recording within the configured interval while preserving distinct events.

The event definitions cover module temperature and voltage, optical-power alarms, resets, receiver signal or lock conditions, error thresholds, firmware changes, and autonomous shutdown. Decode the event identifier and its detail fields instead of treating every record as a generic link alarm.

Score thresholds and event-recording conditions serve different purposes. Do not assume that changing a score boundary changes every event threshold or that a masked score counter stops being useful evidence.

The host APIs expose event retrieval and hysteresis controls for local and remote endpoints. Use those controls deliberately, and preserve module-time validity and sequence context during correlation.

Hysteresis should make the failure story readable. Before clearing a log or resetting counters, retrieve the records that explain the incident and keep them with the host timeline.
