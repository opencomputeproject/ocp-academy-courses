# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
Current telemetry tells you what the link looks like now. Durable event records help explain how it got there.

Each event entry is thirty-two bytes. It contains a sixteen-bit sequence identifier, a sixty-four-bit timestamp expressed in nanoseconds, an event identifier, four detail fields, and reserved space. The fields use little-endian byte order.

The event identifier determines how to decode the details. A temperature event carries temperature information. A receiver event can carry lane bitmaps. A shutdown event records the side, port, triggering category, and metric value.

The circular buffer must preserve existing records across power-up, removal, and reinsertion. Sequence identifiers can wrap, so software must preserve chronological context rather than blindly sorting only the numeric identifier.

Time also needs context. A nanosecond timestamp format does not promise nanosecond clock accuracy. Establish module time and recognize records created before a valid time reference was set.

Command eight thousand ten hex retrieves local or remote history. A different option on that same command clears it. Read and export the evidence before clearing, because durable records are often the only account of a transient failure.
