# pronunciation: CMIS -> C M I S; CDB -> C D B; I2C -> I squared C; SONiC -> sonic; PMD -> P M D; VDM -> V D M; DDMI -> D D M I; SNR -> S N R; PAM4 -> PAM four; MPI -> M P I; FEC -> feck; BER -> B E R; LOS -> L O S; LOL -> L O L; DSP -> D S P; SDK -> S D K; API -> A P I
CDBは、ホストとモジュールに構造化されたコマンド／応答の仕組みを提供します。一般のCMISでは任意ですが、高度テレメトリに準拠する光モジュールでは、テレメトリの収集とホストへの転送に使用することが必須です。

手順は大きく4段階です。必要なコマンドヘッダーとペイロードを準備します。コマンドを発動します。状態レジスタをポーリングします。そして、実行が正常に完了した後で応答を取得します。

各段階がインターフェースの取り決めの一部です。ソフトウェアが応答領域でバイトを見つけただけで、それを運用上のエビデンスにしてはいけません。そのバイトは、実際に完了した要求に対応している必要があります。

測定値の取得、イベント記録の収集、リモートレジスタへのアクセス、ファームウェアの転送でも、同じ手順を守ります。対応するコマンド、選択したエンドポイント、入力フィールド、最終状態を確認します。

これはソフトウェアのデバッグにも役立つモデルです。要求は正しく作成されたか。発動されたか。モジュールは正常に完了したか。ソフトウェアは対応する応答を取得し、検証したか。この4つの明確な問いは、取得方法を説明せずにデータを表示するツールより有用です。
