# pronunciation: OCP -> "O C P"; L.O.C.K. -> "lock"; MEK -> "meck"; MPK -> "M P K"; KMB -> "K M B"; Caliptra -> "Caliptra"; SFR -> "S F R"; TCG -> "T C G"; KIOXIA -> "key-OX-ee-uh"
This is the first of three modules in the O C P lock Academy course.

Here, you'll learn why operators need more assurance than an erase command issued to ordinary drive firmware. You'll classify the threat model, identify the security guarantees, and trace the protected path through Caliptra.

Module two follows the key hierarchy. It explains how data, multi-party, and epoch protection keys combine around a Media Encryption Key. It also compares soft and hard cryptographic erase and the paths for random and derived media keys.

Module three moves into integration. It covers the mailbox and S F R interfaces, command ordering, reset behavior, and the mandatory controls in version one point one.

The specification was contributed through O C P by Google, Microsoft, Samsung Electronics, key-OX-ee-uh, and Solidigm. Their names and official logos appear here as contributor acknowledgments, not as product endorsements. Together, the three modules are designed for engineers who understand storage and basic cryptography but are new to the lock architecture.
