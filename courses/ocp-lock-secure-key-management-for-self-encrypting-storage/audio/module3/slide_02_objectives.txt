# pronunciation: OCP -> "O C P"; L.O.C.K. -> "lock"; KMB -> "K M B"; MEK -> "meck"; SFR -> "S F R"; MPK -> "M P K"; TCG -> "T C G"; KAT -> "K A T"
By the end of this module, you'll be able to separate the two implementation interfaces and explain why both are required.

You'll identify which data drive firmware can control, which values only the K M B can handle, and how the encryption engine stores each media key with metadata and auxiliary information.

You'll sequence the commands that initialize the media-key secret, mix zero or more M P Ks, and then generate, load, or derive the final key. You'll also group the mailbox vocabulary by H P K E discovery, multi-party lifecycle, and media-key lifecycle instead of memorizing one long command list.

Finally, you'll connect T C G host operations to those services and evaluate reset, timeout, authorization, key-cache clearing, and K A T behavior against the mandatory compliance requirements. The goal is not to memorize every byte field. It is to know which ordering and ownership mistakes could expose a key, leave stale key material active, or cause permanent data loss.
